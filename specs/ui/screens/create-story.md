# Create Story Screen

The content selector provides `Văn bản`, `Audio`, and `Nhập vai`. Interactive short stories show the character/timeline editor; interactive serial stories are authored per chapter after Story creation. On small screens the editor columns stack without horizontal scrolling.

This document defines the initial Story creation screen.

---

# 1. Goal

Create the Story container and metadata before the Author begins managing Chapters.

The flow should remain simpler than the full Story Manager.

---

# 2. Entry

Story creation may begin from:

```text
/write
```

with:

```text
Truyện
```

selected.

---

# 3. Product Flow

```text
/write
   ↓
Select Truyện
   ↓
Enter Story metadata
   ↓
Create Story
   ↓
Story Manager
   ↓
Create Chapters
```

Story creation and Chapter writing are separate steps for Truyện dài. Truyện ngắn writes its single
complete body during creation, then opens management for metadata review and publication.

---

# 4. Fields

Initial Story creation supports:

```text
Title
Cover
Description
Tags
Story format: Truyện dài or Truyện ngắn
Complete prose body when Truyện ngắn is selected
```

Slug is generated by the application.

Initial status:

```text
draft
```

---

# 5. Desktop Layout

Recommended:

```text
┌───────────────────────────────────────────────────────┐
│ Header                                                │
├────────────────┬──────────────────────────────────────┤
│ Cover          │ Story Information                    │
│                │                                      │
│ Preview        │ Title                                │
│                │ Description                          │
│ Upload         │ Tags                                 │
│                │                                      │
│                │ [Create Story]                       │
└────────────────┴──────────────────────────────────────┘
```

---

# 6. Title

Required.

Used to generate the initial Story slug.

Example:

```text
Căn phòng ở tầng 13
```

Generated:

```text
can-phong-o-tang-13
```

---

# 7. Slug

The User does not need to manually manage slug during the normal creation flow.

Conceptual flow:

```text
Title
 ↓
Normalize
 ↓
Generate candidate slug
 ↓
Check/reserve atomically
 ↓
Resolve collision if necessary
```

Example collision:

```text
can-phong-o-tang-13
can-phong-o-tang-13-2
```

---

# 8. Cover

Story cover should use approximately:

```text
2:3
```

aspect ratio.

UI supports:

```text
Upload
Preview
Replace
Remove
```

Cloudinary path:

```text
vucdem/stories/{storyId}/cover
```

---

# 9. Description

Story description introduces the Story.

It should support multi-line text.

It is not the first Chapter.

Do not store Chapter content here.

---

# 10. Tags

Allow a bounded list of Story Tags.

Tags help discovery.

Do not use arbitrary unbounded arrays.

---

# 11. Story ID

Generate/reserve a Story ID before media upload when necessary.

This allows Cloudinary path:

```text
vucdem/stories/{storyId}/
```

to be known before uploading the cover.

---

# 12. Initial Document

Conceptually:

```text
authorId = current UID

title = entered title
slug = reserved slug
description = entered description
cover = uploaded asset or null
tags = selected tags

status = draft

chapterCount = 0
viewCount = 0
followerCount = 0

createdAt = trusted timestamp
updatedAt = trusted timestamp
publishedAt = null
```

---

# 13. Create Action

Primary action:

```text
Tạo truyện
```

Flow:

```text
Validate
 ↓
Reserve Story ID
 ↓
Reserve slug
 ↓
Upload cover if selected
 ↓
Create Story document
 ↓
Navigate to Story Manager
```

The exact trusted/transaction ordering must follow database specifications.

---

# 14. Success

After successful creation, navigate to the Story management surface.

Conceptual route:

```text
/story/{id}/manage
```

The final management route should be standardized in the Story Editor feature specification.

Do not send the Author directly into the public reader view as the primary creation workflow.

---

# 15. Draft

New Stories start as:

```text
draft
```

Creating a Story does not automatically publish it.

---

# 16. Publication

Story publication occurs after publication requirements are satisfied.

These may include:

- Valid Story metadata
- At least one publishable Chapter

Exact requirements belong in:

```text
specs/features/stories.md
specs/features/story-editor.md
```

---

# 17. Validation

Show validation errors beside relevant fields.

Do not create the Story if required metadata is invalid.

---

# 18. Loading

During creation:

- Disable duplicate submission
- Show progress
- Preserve form state

Media upload progress should remain visible.

---

# 19. Failure

If creation fails:

- Preserve entered metadata
- Preserve successful upload information where possible
- Allow retry
- Clean orphaned media where practical

---

# 20. Unsaved Changes

Warn when the Author attempts to leave after entering meaningful Story metadata.

---

# 21. Mobile

Mobile order:

```text
Title
Cover
Description
Tags
Create Story
```

Use a single-column layout.

Cover preview should not consume most of the viewport.

---

# 22. Guest

Guests cannot create Stories.

Opening the Story creation flow should request authentication.

---

# 23. Existing Story

This screen is for creating a new Story.

Editing an existing Story belongs to Story Manager / Story Editor.

Do not overload this screen with:

- Chapter management
- Story analytics
- Follower management
- Moderation history

---

# 24. Acceptance Criteria

Story creation UI is complete when:

- Authenticated User can enter Story metadata
- Guest is redirected to authentication
- Title validation works
- Cover uploads through Cloudinary
- Tags respect limits
- Unique slug is generated/reserved safely
- Story is created as Draft
- Trusted counters start at zero
- Duplicate submission is prevented
- Failure preserves User input
- Successful creation opens Story management
- Mobile layout is usable
