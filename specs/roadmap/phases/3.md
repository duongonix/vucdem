## Important Decisions

- Initialize provider SDKs lazily so SSR and builds work without real environment credentials; integrations fail with a typed configuration error only when requested.
- Keep SDK access synchronous after lazy initialization and reuse the default Firebase App/Auth/Firestore instances across HMR and component boundaries.
- Make document decoding explicit through codecs; converters do not use unchecked casts to pretend unknown Firestore data matches domain models.
- Pre-bundle the three modular Firebase entry points used by browser tests so provider registration and app initialization share one module graph.
- Do not add Firebase CLI/rules in this phase; the roadmap assigns the security rules and emulator rule tests to Phase 6.

## Known Limitations

- Live project connectivity requires valid values in a local `.env` or deployment environment.
- A Cloudinary API secret was previously present in `.env.example`. The repository copy is sanitized, but that credential must be rotated in Cloudinary because prior exposure cannot be undone locally.
- Pnpm installed the SDK while intentionally blocking optional dependency build scripts under workspace supply-chain policy; direct imports, Auth, Firestore, tests, and production build all work without relaxing that policy.
