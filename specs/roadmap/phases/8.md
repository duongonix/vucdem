## Database Changes

- No new fields or collections. Uses `usernames/{normalizedUsername}` and `users/{uid}` exactly as specified.

## Security Changes

- Public response omits account status and timestamps.
- PATCH requires a verified Firebase ID token and exact owner UID.
- Strict input accepts only display name, bio, and canonical owned avatar metadata.
- Avatar URL must use the configured `res.cloudinary.com/{cloudName}/image/upload/` delivery namespace.
- Trusted role, status, counters, username, identity, and timestamps cannot be supplied.

## Specs Added or Updated

- Added Profile feature and API contracts.
- Added canonical 300-character bio limit.

## Important Decisions

- Username editing remains deferred because safe migration requires an atomic reservation workflow beyond normal profile editing.
- Avatar removal updates Firestore first, then performs Cloudinary cleanup, avoiding a public profile that references an intentionally deleted image.
- Trusted server endpoints are used because Phase 6 remains intentionally skipped.

## Known Limitations

- Follow actions and profile content tabs belong to later phases.
- Live profile/avatar verification requires configured Firebase Admin and Cloudinary credentials.
- Full integration/E2E testing remains deferred to the testing phase.
