## Dependencies Added

- None.

## Database Changes

- Implements the existing `posts/{postId}` schema without adding fields.
- Adds six documented Post composite indexes.
- First publication increments `users/{uid}.postCount` once; logical removal of a published Post decrements it once.

## Security Changes

- All writes verify Firebase tokens and Post ownership through Firebase Admin.
- Author snapshots come from the server-read User document.
- Strict request schemas exclude trusted counters, author fields, timestamps, excerpt, and hidden/moderation states.
- Media metadata must match the configured Cloudinary cloud and exact `vucdem/posts/{postId}` namespace with unique numbered slots.
- Draft reads return not found to unrelated Users and Guests.

## Specs Added or Updated

- Added Post API and index contracts.
- Explicitly selected plain text as the MVP Post content storage/rendering format.
- Added publication, excerpt, Tag, image-count, and category limits.

## Important Decisions

- Use logical `removed` state rather than physical cascading deletion.
- Filtered feeds support newest order only until additional ranking indexes are explicitly required.
- Cursor includes sort value plus document ID, preventing unstable pagination ties.

## Known Limitations

- Firestore Rules remain Phase 6 work; current Post operations use trusted server endpoints.
- Community membership/posting authorization cannot run until Community persistence exists; Phase 10 therefore sends `communityId = null`.
- View counting and physical cleanup belong to later phases.
- Full live CRUD and index testing requires configured Firebase credentials and is deferred.
