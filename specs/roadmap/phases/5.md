## Dependencies Added

- `firebase-admin` — trusted Firebase ID-token and Firestore server operations.
- `zod` — shared runtime request/form validation.

## Database Changes

- Implements the existing `users/{uid}` and `usernames/{usernameNormalized}` schemas.
- Username reservation and User creation occur in one Admin Firestore transaction.
- No new persistent field, collection, or enum was introduced.

## Security Changes

- Profile creation verifies the Firebase ID token and derives UID server-side.
- Browser requests cannot select role, account status, UID, counters, or trusted timestamps.
- Redirects accept only normalized same-origin absolute paths.
- Firebase Admin credentials remain server-only.

## Specs Added or Updated

- Added the previously referenced shared validation specification.
- Updated environment-variable documentation for Application Default Credentials and optional explicit Firebase Admin service-account values.

## Important Decisions

- Use a trusted profile endpoint rather than depend on client-side profile creation while Phase 6 rules are intentionally skipped.
- Keep one global Auth listener; route/components consume the store instead of creating listeners.
- Google authentication without an application profile always enters username onboarding.

## Known Limitations

- Live provider verification requires configured Firebase Web and Firebase Admin credentials.
- General Firestore client Security Rules are intentionally not implemented because the user requested skipping Phase 6; trusted Phase 5 writes use Admin authorization instead.
- Full integration/E2E testing is deferred until the roadmap testing phase per user direction.
