## Important Decisions

- Use `@lucide/svelte` instead of the deprecated `lucide-svelte` package; the icon-system role and product behavior are unchanged.
- Keep Firebase runtime initialization out of Phase 0. This phase establishes the boundary and env contract; the roadmap's Firebase phase owns the SDK and live configuration.
- Configure an actual shadcn-svelte-compatible primitive rather than treating the presence of a config file as sufficient proof of integration.
- Use `adapter-auto` during foundation work. The previous Vercel adapter selected a deployment target before Phase 42 and required Windows symlink privileges merely to complete a local build.

## Known Limitations

- Firebase and Cloudinary are not connected to live projects in this foundation phase.
- The foundation landing screen is a technical checkpoint; the complete visual system begins in Phase 1.
- `adapter-auto` intentionally reports that no production platform is selected; target selection and deployment remain Phase 42 scope.
