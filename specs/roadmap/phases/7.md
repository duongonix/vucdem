## Dependencies Added

- `cloudinary` — official server-side signing, metadata lookup, and deletion SDK.

## Database Changes

- None. Ownership checks use existing `authorId` and `ownerId` fields.

## Security Changes

- Firebase ID tokens are verified server-side with revocation checks.
- Folder/public ID, owner context, format allowlist, and overwrite policy are server-selected signed values.
- Deletion refuses arbitrary namespaces and requires resource plus Cloudinary context ownership.
- Cloudinary API secret remains private and never enters the browser response.

## Specs Added or Updated

- Added Cloudinary sign/delete API contracts, Cloudinary security rules, and shared image validation limits.

## Important Decisions

- Use direct browser upload to avoid proxying image bytes through SvelteKit.
- Allow preallocated Post/Story IDs before persistence, but force `overwrite = false` until the owned Firestore document exists.
- Community uploads require an existing owned Community because Community creation is not yet implemented.

## Known Limitations

- Live upload/delete requires configured Firebase Admin and Cloudinary credentials.
- Cloudinary account/upload policy must enforce the documented maximum byte size because direct uploads prevent the signing endpoint from independently reading the file bytes.
- Feature-specific upload UI integration occurs in the relevant profile, Post, Story, and Community phases.
- Full integration/E2E testing is deferred until the roadmap testing phase per user direction.
