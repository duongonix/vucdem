## Important Decisions

- Firestore document IDs are represented as application-level `id` fields and are not intended to be duplicated in persisted document data.
- Guest is an application role but not a persisted User role.
- Relationship document identity is derived from the document path, preventing duplicate votes, bookmarks, and follows by construction.

## Known Limitations

- Persistence services and Firestore security rules are implemented in later roadmap phases.
- Full cross-feature and E2E testing is deferred until the roadmap testing phase at the user's request.
- Raw `tsc` is not a valid standalone SvelteKit gate because it does not load Svelte's generated component declarations; the canonical `svelte-check` gate passes with no diagnostics.
